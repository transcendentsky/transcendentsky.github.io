> 当大多数团队还在靠人力调参、手动写数据时，XYZ AI Lab 已经让 300 多个 Agent 在千卡级算力上自动完成从故障诊断、数据构造、模型训练到运行时优化的完整研发循环。这不是某个"超级模型"的胜利，而是一套"有边界的 AI4AI 系统"对传统研发模式的系统性超越。

2026 年 7 月，XYZ AI Lab 发布了他们的 Search Agent 家族——XYZ-Aquila，以及支撑其诞生的完整技术报告《AI4AI at Scale: A Full-Pipeline System for Enhancing LLM Agentic Capabilities》。这份报告的分量远不止又一个"刷榜模型"：它展示了一条与业界主流完全不同的路径——**不是靠更大的模型、更多的参数，而是靠一套"人类设定边界 + AI 自动迭代"的 AI4AI 系统，将智能体研发从"手工作坊"推进到"可验证、可复现、可积累"的工程化阶段**。

XYZ-Aquila-mini（35B 级）在 7 大搜索基准的 <40B 开放权重榜单中全部位列第一；XYZ-Aquila-pro（397B 级）则在 <400B 开放权重组的 6 项基准中全部领跑，并在 BrowseComp-ZH、LiveBrowseComp 和 WideSearch 上创下所有公开系统中的最高记录。更重要的是，这些结果不是靠"堆料"堆出来的，而是通过一套有边界、可审计的 AI4AI 循环系统地优化出来的。

本文将从核心框架、技术细节、Benchmark 结果和人机协同模式四个维度，深度拆解 XYZ-Aquila 背后的研发方法论。

## 一、AI4AI 的核心不是"全自动"，而是"有边界的递归优化"

AI4AI（AI for AI）这个概念并不新鲜——用 AI 来帮助研发 AI，过去几年已有不少探索。但 XYZ AI Lab 的做法有一个本质区别：**他们不追求"让 AI 完全替代人做研发"，而是设计了一套"人类定义契约 + AI 在边界内搜索 + 独立评估门控 + 经验持续沉淀"的闭环系统**。

这套机制的核心可以用五个步骤来描述：

### 1. 设定契约（Set the Contract）
人首先定义清楚：目标能力是什么、用哪些私有 Benchmark 做代理、允许哪些类型的干预（数据/训练/运行时/上下文/基础设施）、资源预算有多大、风险边界在哪里、验收标准是什么。这相当于给 AI 画了一个"操场"——你可以在里面自由跑，但不能跑出界。

### 2. 诊断故障（Diagnose Failures）
Agent 分析运行轨迹、日志、评审意见、成本和可靠性信号，找出当前系统的问题在哪里。这里的关键是：诊断不是靠人的直觉，而是靠对可观测数据的系统性分析。

### 3. 提出变更（Propose Changes）
Agent 基于诊断结果，提出有范围的改进方案——可能是构造新的训练数据、调整 SFT 配方、优化运行时策略、改进上下文管理，或者调整基础设施。每一个变更都是一个"候选补丁"，而不是对系统的全面改写。

### 4. 门控采纳（Gate Adoption）
一个独立的评估器在不暴露私有标签或答案的前提下，对候选变更进行测量。只有通过了人类定义的验收门控的变更，才会被采纳到主系统中。这一步是防止"AI 乱改"的关键防线。

### 5. 沉淀经验（Bank Experience）
无论被采纳还是被拒绝，每一次尝试都会连同来源、决策状态一起被保留进共享记忆。被拒绝的经验同样有价值——它告诉系统"这条路走不通"，避免未来重复踩坑。

这五个步骤构成的循环，是 XYZ-Aquila 能够持续迭代的底层引擎。**它的递归性体现在：每一轮优化的结果，都会成为下一轮优化的起点；但它的开放性又被严格限制——目标、边界、验收标准始终由人掌控**。

## 二、为什么 Deep Search 是 AI4AI 的"高压试验场"

XYZ AI Lab 选择 Deep Search（深度搜索）作为 AI4AI 的试验场景，不是随意决定的。一次深度搜索任务，往往需要经历：

- **问题拆解**：把一个复杂的用户问题拆成多个可检索的子问题
- **网页检索**：调用搜索引擎获取初步结果
- **来源判断**：评估哪些来源可靠、哪些可能有偏见
- **跨页面比较**：对比不同来源的信息，识别冲突和互补
- **计算与推理**：对检索到的数据进行计算、推理和整合
- **证据核验**：回溯关键信息的来源，确保答案有据可依
- **最终作答**：在约束条件下生成有引用、可审查的答案

在这个过程中，网页会超时、搜索结果会跑偏、来源可能冲突、关键证据也可能在长流程中被折叠或淹没。**一次回答碰巧正确，不代表中间过程可靠**。Deep Search 的难度恰恰在于：它要求的不只是最终结果对，还要求过程可追溯、可验证、可复现。

而这正是 AI4AI 系统最需要的"压力测试"。如果一套 AI4AI 机制能在 Deep Search 这种充满噪声、延迟、异常和长程依赖的场景下稳定工作，那么它就有很大概率能迁移到其他复杂的智能体研发场景。

## 三、XYZ-Aquila 的技术内核：不止是一个模型，而是一套系统配置

XYZ-Aquila 最容易被误解的地方，是把它当成一个"训练得很好的模型"。但技术报告反复强调：**XYZ-Aquila 是一个系统配置（system configuration），而不只是一个模型检查点（model checkpoint）**。

一个 XYZ-Aquila 智能体 = 骨干模型 + 图驱动的数据构造 + 状态对齐的监督微调 + 固定三工具执行协议 + 上下文管理 + 回放基础设施 + 版本化评估门控。这七个部件缺一不可，协同工作才产生了最终的能力。

### 1. 图驱动的任务构造（Graph-grounded Task Construction）

传统的搜索 Agent 训练数据，往往是"问题-答案"对，或者最多加一个引用链接。但 XYZ-Aquila 的做法完全不同：他们先把网页通过链接、引用、共享实体和时间关系连接成一张图，再在这张图上生成问题、答案、支持路径和约束。

这样构造出来的任务有一个关键性质：**它必须是在固定工具环境下"可检索"的，答案必须唯一，来源链必须可靠，而且不存在明显的查询捷径**。换句话说，如果一个问题靠"直接搜一下关键词"就能答出来，它不会进入训练集；只有那些需要真正的"多步搜索 + 证据整合 + 交叉验证"的任务，才会被保留。

同时，整个数据构造过程严格遵守"答案隐藏契约"（answer-hidden contract）——执行训练的 Agent 永远看不到评估端的标签，从根源上防止了标签泄露。

### 2. 状态对齐的监督微调（State-faithful SFT）

很多 Agent 训练有一个常见问题：训练时给模型看的是"上帝视角"的完整信息，但实际运行时模型只能看到"当前步可见"的信息。这种不一致会导致训练好的模型在真实场景中表现下降。

XYZ-Aquila 的做法是：**保留完整的审计日志和每一步的可见状态（visible state），训练时重建模型当时实际能获得的信息，只监督有效的推理、工具调用和最终作答**。这被称为"状态对齐的监督微调"（state-faithful SFT）。

举个例子：一条成功的搜索轨迹可能同时包含网页超时、格式错误、无效重复尝试和后续的恢复过程。训练时不是把这些"失败片段"删掉，而是完整保留——因为模型需要学会的，正是在这些真实的噪声和异常中如何做出正确的决策。

### 3. 固定三工具的运行时协议（Fixed Three-Tool Runtime）

XYZ-Aquila 在运行时只能调用三个工具：`search`（搜索）、`scrape`（网页抓取）和 `python`（代码执行）。工具的语义、可见上下文限制、轮次预算都是固定的，不允许在优化过程中偷偷增强工具接口。

这个"不变性原则"（Invariance Principle）是整个系统诚实性的关键保障。**候选变更带来的能力提升，不能来自于"工具变强了"或"上下文变大了"，而必须来自于"模型用工具的方式变聪明了"**。

运行时还通过只增不改的审计日志（append-only audit log）和逐步可见状态，让团队能够精准定位不同类型的问题：
- 是**证据从未被找到**（检索问题）？
- 还是**证据已经存在但没有被正确呈现**（上下文管理问题）？
- 抑或是**Agent 已经获得证据却没能用于最终回答**（推理整合问题）？

这种可观测性，是 AI4AI 能精准诊断并修复故障的前提。

### 4. 自适应工具使用的涌现

有趣的是，在固定三工具的约束下，XYZ-Aquila 在不同基准上展现出了不同的工具使用偏好：

- 在 BrowseComp、BrowseComp-ZH 和 LiveBrowseComp 上，搜索（search）占了 78–84% 的调用量——这些任务更依赖广度检索；
- 在 DeepSearchQA 和 GAIA 上，网页抓取（scrape）和 Python 计算加起来占了 54–55%——这些任务更需要深度信息提取和逻辑计算。

这说明：**强搜索智能体需要的不是固定的交互模板，而是灵活的工具分配能力**。系统不应该预设"什么时候该用什么工具"，而应该让模型在训练中学到根据任务类型自适应地调配工具。

## 五、人机协同的新范式：从"人盯每一步"到"人管规则+AI 跑流程"

XYZ-Aquila 的研发过程中，有一个数字特别值得关注：**300 多个 Agent Workers，只需要十余名研究人员来组织和监督**。这是怎么做到的？

答案在于他们设计的人机协同模式。人不需要逐个跟进每一次实验，而是通过三种方式与 AI 协作：

### 1. 沉淀经验（Banked Experience）
人类和 AI 共同积累的经验（包括成功的和失败的）都会进入共享记忆。当遇到类似问题时，系统可以自动回顾历史上哪些方案有效、哪些无效，不需要人每次从头开始指导。

### 2. 验证人的候选想法（Validate Human Candidates）
当人类研究者有一个改进想法时，不需要自己动手实现和验证——可以把想法交给 Agent 去执行，系统会通过独立评估器来判断这个想法是否真的有效。这相当于把人的"直觉"和 AI 的"执行力"结合起来。

### 3. 通过阶段报告持续调整方向（Steer via Periodic Reports）
Agent 会定期生成进度报告，总结当前的进展、问题和建议。人类研究者不需要盯着每一个微动作，只需要在这些关键节点上阅读报告、调整优先级、处理异常情况，并设定下一阶段的方向。

这种分工模式让 300 多个 Agent 不是 300 个各自决策的"数字研究员"，而是由统一系统编排、各自承担特定任务的执行单元。**人类负责确定方向、设定边界和做出关键判断；Agent 则负责问题拆解、方案探索、实验执行、结果汇报和经验整理**。

这也呼应了我们之前讨论过的一个观点：高等级 Agent 的出现，不是让人类更轻松，而是让人类的监督方式更抽象、责任也更重。低等级系统需要操作手册，高等级系统需要治理架构。

## 六、三条原则，确保 AI4AI 的诚实性

AI4AI 最大的风险之一，是"优化了半天，其实只是过拟合了开发分布"或者"偷偷放宽了约束"。为了应对这个问题，XYZ AI Lab 提出了三条核心原则：

### 原则一：隔离性（Isolation）
外部基准始终保持在优化状态之外，只用于最终或明确授权的评估。换句话说，日常优化用的是私有的开发集，公开基准只是"期末考试"，不能拿来当"日常练习"。

### 原则二：不变性（Invariance）
候选方案的能力提升，不能来自于额外的工具、更大的可见上下文或更多的轮次预算。所有候选方案必须在相同的工具和约束下进行公平比较。

### 原则三：可审计性（Auditability）
每一个被监督或被分析的决策，都必须与该步骤可用的确切可见状态绑定。你不能事后用"上帝视角"的信息来解释一个当时不该知道的决策。

这三条原则听起来简单，但在实际操作中非常难坚持。很多团队在优化过程中会有意无意地"放宽条件"——比如给 Agent 加一个新工具、把上下文窗口开得更大、或者在训练时混入了评估集的信息。短期看这些操作能"提分"，但长期看会严重损害系统的泛化能力和可信度。

## 七、局限性与未来方向

技术报告并没有回避自身的局限，这种坦诚反而增加了它的可信度：

### 1. 因果归因尚不完整
报告评估的是"端点系统"（endpoint systems），而不是对数据、训练、运行时和上下文等干预路径的完整分解。哪些组件是因果必要的、哪些只是锦上添花，还需要通过受控再训练和有针对性的因子消融来进一步确认。

### 2. 自适应过拟合风险仍然存在
评估隔离减少了但不能完全消除对私有开发分布的自适应。旋转数据分割、刷新隐藏留出集、定期进行迁移审计，仍然是必要的保障措施。

### 3. 可比性和成本信息不足
部分基线来自不同的工具、裁判、日期和活网条件。报告还缺乏端到端的计算、延迟、工具、评估器和人工评审的成本核算。

### 4. RL 和迁移验证仍然有限
一个过程奖励 RL 设计通过了低成本筛选，但尚未完成完整的训练和门控路径，因此未被计入发布系统。目前的经验验证也仅限于 Deep Search 和两个骨干模型。

这些局限性恰恰说明：XYZ-Aquila 不是 AI4AI 的终点，而是一个经过严格验证的起点。它证明了"有边界的系统级优化"这条路走得通，但这条路能走多远、能迁移到哪些场景，还需要更多的探索。

## 写在最后

XYZ-Aquila 给行业带来的启发，远不止"又一个刷榜的 Search Agent"。它真正的价值在于：**演示了一条不靠"堆参数"、而是靠"系统化研发方法论"来提升智能体能力的路径**。

在这条路径上：
- 人不再需要做"人肉调参师"，而是成为"规则制定者"和"边界守护者"；
- AI 不再只是"执行人类指令的工具"，而是能够在边界内自主诊断、自主尝试、自主积累经验的"研发协作者"；
- 研发过程不再是一堆"灵感驱动的零散实验"，而是一个可验证、可复现、能够持续沉淀经验的工程化闭环。

当然，这套方法论目前还只在 Deep Search 一个场景中得到了验证。它能否同样有效地应用于代码智能体、科研智能体、运维智能体等其他领域，还有待观察。但它至少证明了一件事：**当我们谈论"AI 研发 AI"时，不需要追求科幻式的"完全自动"，而是可以从"有边界的系统优化"开始，一步一步地把研发效率推向新的高度**。

XYZ-Aquila 的技术报告标题中有一个关键词——"Bounded Exploration"（有边界的探索）。这或许是整个 AI4AI 领域最值得深思的一个短语：**真正强大的系统，不是什么都能尝试的系统，而是知道在什么边界内尝试、如何验证尝试的结果、以及如何从每一次尝试中学习的系统**。
